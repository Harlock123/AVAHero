# AGENTS.md

Notes for anyone, human or AI agent, changing this code. `README.md` covers playing the game, its controls and
what the tests check; this file covers how the code is put together and the rules that keep it working.

## What this is

A mine rescue in the style of John Van Ryzin's 1984 Activision game H.E.R.O., in C# on .NET 10 and Avalonia 12,
drawn through Avalonia's `DrawingContext`. One self-contained executable per platform (Windows, macOS and Linux, x64 and ARM).
Everything in it is original: the graphics are drawn in code, and the sounds, music and the miner's voice are
synthesised by `tools/make_sounds.py` (the voice through `tools/speech.py`; the mine music is Grieg's
public-domain In the Hall of the Mountain King).

## Commands

```bash
dotnet build AVAHero.slnx                         # the SDK version is in global.json (10.0.400 or later)
dotnet test AVAHero.slnx                          # every test runs headless: no window opens
dotnet run --project src/AVAHero                  # play it; --no-audio for silence
HERO_SHOTS=$PWD/Images dotnet test tests/AVAHero.Tests --filter ScreenshotTests   # refresh the README's pictures
HERO_PROBE=1 dotnet test tests/AVAHero.Tests --filter PilotProbe   # how the computer hero fares, for tuning
python3 tools/make_sounds.py                      # rebuild src/AVAHero/Sounds (standard-library Python only)
```

`Directory.Build.props` sets `TreatWarningsAsErrors`, nullable reference types and implicit usings for every
project: a warning fails the build, so keep it at zero.

## Layout

- `src/AVAHero/Engine/`: the game, with no Avalonia drawing in it.
  - `GameEngine.cs` runs the states (title, attract, play, pause, game over, initials, high scores) and the
    fixed-step loop.
  - `Sim.cs` steps the mine: the hero's prop-pack, the dynamite, the laser, the creatures, power and death.
  - `Mine.cs` has the measures (`Field`), the tiles and creatures, and `MineBook`, which builds the twenty levels.
  - `World.cs` has `Controls`, the seeded `Dice` and the `World` that holds everything that moves or changes.
  - `Pilot.cs` is the computer hero, used by the attract mode and the tests. It tries each move on a copy of the
    world, so a new field in `World` must also go into `World.Copy`.
  - `InputHandler.cs` (keys) and `ControllerManager.cs` (SDL2 gamepads) produce `Controls`.
  - `HighScoreTable.cs`, `InitialsEntry.cs` and `SoundManager.cs` do what their names say.
- `src/AVAHero/Views/`: `GameCanvas` (split over two partial files) draws the 1024x768 frame and runs the 60 Hz
  timer.
- `src/AVAHero/Audio/`: the OpenAL Soft audio engine, shared with the author's other AVA games.
- `src/AVAHero/Sounds/`: the WAV files the game plays, generated by `tools/make_sounds.py`.
- `tests/AVAHero.Tests/`: xUnit v3 with `Avalonia.Headless.XUnit`: `GameplayTests`, `ScreenshotTests` and the
  opt-in `PilotProbe`.

## Rules that keep it working

- **Fixed steps.** `GameEngine.Update` advances the game in fixed 1/60 s steps (`Sim.Step`, `Field.Step`),
  independent of the frame rate, so tests can play whole levels deterministically. The simulation itself uses no
  random numbers; the mines are built by `MineBook` from a seeded `Dice`. Keep it that way: never use
  `Random.Shared`.
- **Engine first, drawing second.** Gameplay belongs in `Engine/`, where tests can reach it without a window.
  `Views/` only reads the world and draws it.
- **Input goes through `InputHandler`.** There is no `dy`: `Controls` is `Dx`, `Up` (fly), `Down` (dynamite) and
  `Fire`. Up on keys or D-pad, or a negative stick Y, means fly. Test new controls through `InputHandler`, not by
  setting `Controls` directly.
- **SDL under one lock.** `ControllerManager` starts, polls and stops SDL only inside `lock (Sdl)`. The tests
  create many handlers in parallel, and unlocked SDL calls corrupt its heap.
- **Audio.** OpenAL Soft through Silk.NET. `Directory.Build.targets` swaps in the official Windows `soft_oal.dll`
  from `Audio/native/`, which needs no Visual C++ runtime. In a virtual machine `OpenAlConfig` writes a larger
  mixing period to `ALSOFT_CONF` so the sound doesn't break up.
- **Tests never touch the player's files.** High scores live in the app-data folder (`AVAHero`); tests load the
  table from a temporary folder and run silent (`Silent = true`).

## Making a change

- Add or update tests with every gameplay change. `dotnet test` must pass, with no warnings.
- If the change shows on screen, refresh the screenshots with the command above, and look at them.
- Update `README.md` (features, controls, the test list) to match.
- New sounds and spoken words go into `tools/make_sounds.py`, not as hand-edited WAV files.

## CI and releases

`.github/workflows/build.yml` builds and tests every push. It then publishes self-contained single-file builds for
win-x64/x86/arm64, linux-x64/arm64/arm and osx-x64/arm64. Every run keeps the builds as workflow artifacts.
Only pushes to `main` replace the assets of the `latest` pre-release, and a `v*` tag makes a proper release.
A release run then asks the portfolio site to rebuild, if the `SITE_REFRESH_TOKEN` secret is set.
